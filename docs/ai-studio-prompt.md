# Steps 5–8: AI Studio structured output, error capture, and fixes

> **Honesty note.** The two runs in `data/generated/` are **simulated**: they were authored to behave like real model output (including typical mistakes) so the pipeline, tests and UI could be built end to end. To satisfy the lab with real output, repeat the steps below in Google AI Studio and overwrite those two files. The validator, tests and UI will tell you immediately whether your real output passes.

## AI Studio setup

1. Open Google AI Studio → **Create prompt**.
2. Right panel → **Structured output** → **Edit** → paste the contents of `schemas/dist/property-batch.ai-studio.schema.json` (generated by `npm run schema:bundle`; it has no `$ref`, which AI Studio can't resolve across files).
3. Settings: temperature 0.4, response MIME type `application/json`.
4. Paste the prompt below. Take a screenshot with personal data and API keys removed and save it as `docs/evidence/ai-studio-export.png` (see `docs/evidence/README.md`).

## Prompt: run 002 (after fixes)

```text

Rules:

- zip_code is exactly 5 digits as a string.

                                  /amenities/0     enum                 must be equal to one of the allowed values
```

The raw file was **never edited**. The fix goes in a different layer, then we regenerate.

## Step 8: which layer fixed each error

| Error in run 001 | Root cause | Layer that fixed it | Fix |
|---|---|---|---|
| `/price` was `"$398,000"` | Model copied the human format from the notes | **Prompt** | Explicit "whole number, never `$398,000`" rule; the schema description for `price` already said so but the model ignored it under free text |
| `/zip_code` was `"8020"` | Model dropped a digit | **Validator** (cannot be prevented reliably) | Prompt asks for 5 digits, but only the schema `pattern` guarantees it. Records that still fail are rejected, not repaired |
| `/lot_size_sqft` extra field | Model added a plausible field | **Schema + prompt** | `additionalProperties: false` rejects it locally; "Output ONLY fields defined in the schema" removes it at the source |
| `/amenities/0` was `"Hardwood Floors"` | Free-form label vs controlled vocabulary | **Schema** | Amenity `enum` in the structured-output schema constrains decoding to allowed values |
| `/bedrooms` was `5.5` | Model "split" bedrooms | **Schema** | `type: integer` in both the response schema and local validator |

Run 002 result: 5 valid, 0 rejected.

## If structured output is unavailable for your model

Paste the schema into the prompt text, ask for "JSON only, no markdown fences", and rely on the local validator as the enforcement layer. Document the limitation in the ADR "Consequences" section. Some structured-output implementations support only a subset of JSON Schema (for example `pattern`, `multipleOf` or `uniqueItems` may be ignored); that is why the local validator stays authoritative.
